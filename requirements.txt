# The robot lane runs on the published spatialdds_ros library rather than on
# this repository's own robot_bridge. **Pinned to a release, not a commit.**
# Every consumed artifact in this programme is pinned and bumped deliberately:
# a library change should be a decision with a diff to read, not something a
# rebuild picks up silently.
#
# **The demo consumes releases.** It is the library's first consumer, and that
# proof is strongest against the artifact users get -- the same way the
# gateway embeds `spatialdds` from PyPI (run_bridge_server_docker.sh). A git
# commit pin is for the window of developing against an unreleased fix, and
# goes back to a release once one carries the fix.
#
# Bumped e8e5ec2 -> e7b897d on 2026-10-19: that release added `content_refs`
# and `external_refs` to its Config, which is what the robot lane needed. The
# earlier pin could not be adopted — the library had nowhere to carry this
# robot's `catalog:` reference, so the page would have drawn a pin instead of
# a TurtleBot. See docs/ros-adoption-blocker.md.
#
# Bumped e7b897d -> aa52a74 (0.2.1) on 2026-10-19: the two library findings
# the adoption produced, both fixed. Its `take_samples` now reads sample
# state, which retires the labelled `InvalidSample` workaround in
# `robot_bridge._run_kinematic`; and its topics carry default QoS, so the
# topic-QoS collision that forced the keep-out reader onto the library's
# transport is gone. See docs/ros-adoption-findings.md.
#
# Note it ships a top-level `spatialdds_idl18` of its own. Since the SDK
# adoption retired this repository's copy, the robot lane imports the
# library's and everything else the SDK's types; `tests/test_idl_trees_agree.py`
# holds the two to the same minimal XTypes identities, because a mismatch
# between two generated trees shows up as a plausible wrong value rather than
# an exception.
#
# Moved aa52a74 (0.2.1, git) -> 0.3.0 (PyPI) on 2026-10-21. 0.3.0 is the first
# published release; its library code is 0.2.1's, and the change is packaging
# (install_requires is `cyclonedds>=0.10`, already met by the demo image's
# 11.0.1). Robot-lane acceptance re-run on it: see docs/ros-adoption-findings.md.
# 0.3.0 -> 0.4.1 on 2026-10-25. 0.4.1 fixes what this repository's SDK
# acceptance found (its findings 10 and 11): a dead sim stayed ACTIVE, and
# nav2's answers to goals reached no client. It also brings 0.4.0 aboard for
# the first time: the pose floor, writers that do not dispose on exit, and the
# awareness node, installed and unconfigured (it refuses to start without its
# parameters).
# 0.4.1 -> 0.4.2 on 2026-10-28: nav2 reporting success far from the goal
# (the preemption the OWM 0.2 prototype measured, its finding 12) reaches the
# robot's record as a refusal, in `nav.status`, rather than nothing.
# 0.4.2 -> commit cb38ec2 -> 0.5.0 (PyPI) on 2026-11-08: the claims batch
# (docs/ros-claims.md) developed against the unreleased commit, and 0.5.0 is
# that commit released (tag spatialdds-ros-v0.5.0 at cb38ec2; the PyPI wheel's
# payload matches a build of the tag, 86 files). It brings the claims layer the
# robot tier now runs, perception publishing, and the relationship type.
# Rebuild the tier image when this moves (robot_tier/README.md).
spatialdds_ros==0.5.0

# (`[dds]`) and the embedded gateway the web bridge serves the binding with
# (`[server]`). One pin for both, from PyPI, because the demo is the SDK's
# first consumer and the proof is strongest against the artifact users get.
# Moved onto it 2026-10-24 (docs/sdk-adoption-census.md); the binding was a
# separate `spatialdds[server]==0.5.4` until then, installed on top of this
# file at container start, and that second install is gone so it cannot
# downgrade this one. 0.7.1 -> 0.7.2 the same day: 0.7.2 adds `sd.dds.extend`,
# without which this repository's own `oarc.*` types could not be converted,
# keyed or recorded by the SDK (spatialdds-py finding 69, found here).
# 0.7.2 -> 0.7.3 on 2026-10-25: §2's lane templates open (the plan lane the
# bridges read), frames carry their derived uuid (so SDK announces pass this
# repository's discovery core), and an announce lists the lanes a service reads
# (spatialdds-py finding 70, S11-S15, found here).
# 0.7.3 -> 0.7.4 on 2026-10-28: what this repository found, fixed (findings
# 71 and 72), and the three labelled workarounds for it gone. `sd.stamp`
# normalises (S16), so `payloads.stamp` is retired; `close()` reads
# cyclonedds' ack-timeout AttributeError as the timeout it is (S17), so
