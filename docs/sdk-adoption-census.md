# The demo adopts the native SDK: the census

**Origin.** `demo-adopts-sdk-brief.md` (2026-10-24): `spatialdds_demo` stops
being this programme's private standard library and moves onto
`spatialdds[dds]` 0.7.0 from PyPI. This is the brief's one stop. It maps
every module of `spatialdds_demo` and every demo-side call site to a verdict:
**REPLACED** by the SDK (named equivalent), **STAYS** (venue- or demo-specific
logic), or **RETIRED** (nothing needs it once the SDK is in). The rulings
requested are at the end.

**How the numbers are made.** Every count and table below the "Tables" marker
is generated by `tools/sdk_adoption_census.py` from the git-tracked tree at
`1ec933d`, with `ast`. The verdicts are data in that tool. It refuses a
symbol that has no verdict, and `--check-sdk` imports every named SDK
equivalent from the installed release. Run against 0.7.0, every equivalent
exists. Two claims from spatialdds-py's own census fit map are wrong at
0.7.0, and the check refuses both when planted (`p.blob_writer()` and SDK
absent-value constants; see "Corrections"). `--check-doc` fails if the tables
here drift from the tree.

**What was measured, and against what.** Every probe ran against
`spatialdds[dds]==0.7.0` installed from PyPI into a clean venv (cyclonedds
11.0.1, Python 3.12), on its own DDS domain (150–229). The per-file reading of
the consumers was done file by file, and each claim cites its line. The
claims that change a verdict were re-checked here before they were used.

## The headline

**The venue's plumbing has an SDK equivalent for almost everything, and 0.7.0
carries the types, names, QoS and JSON for all of it.** What 0.7.0 does not
carry is how this repository's programs *read* and *where* they write. Three
gaps reach nearly every consumer:

1. **There is no non-blocking read (S1).** `Reader.events()` is a blocking
   generator. Every live consumer here reads by draining in a loop it already
   owns: a tick, an rclpy timer, a FastAPI handler, or a pump thread over
   twenty readers. The drain exists in 0.7.0, but only as the private
   `Reader._events()`.
2. **Every lane is scene-shaped (S2).** `_Lane` builds each topic as
   `topic_name(scene, stream, type)` (`_participant.py:110-158`). That gives no
   way to reach `spatialdds/vps/*`, `spatialdds/bootstrap/*`, a coverage reply
   topic the asker names, `spatialdds/anchors/<set>/delta/v1`, or another
   scene's lanes. The AR lane's services and all four bridges need those.
3. **The announce is single and fixed (S3).** `p.announce()` cannot carry
   `transforms` (the AR catalogue's frame-to-earth placement,
   `ar_demo/spatialdds_catalog_server.py:167`). One participant cannot
   announce more than once (`synthetic_publisher.py:500-508` announces N+1
   services). A bridge or replayer cannot relay someone else's announce
   (`mcap_bridge/replayer.py:178-191`).

**Recommendation: a small 0.7.1 before the migration.** It would carry S1–S5
and S9. Each is a few lines over code 0.7.0 already has, and without them every
consumer gets a hand-rolled reader thread (the pattern the SDK exists to
retire), or a raw-cyclonedds island beside the SDK. With 0.7.1 the venue,
ducks, keep-out, browser binding and recordings move in this batch, and so do
the AR lane and the bridges. The alternative is to move only the venue core now
on 0.7.0, with one labelled reader-pump workaround, and leave the AR lane and
the bridges on `typed_transport` until 0.7.1. That alternative is costed under
"Rulings requested".

## Measured today

**The pin moves `9c3e1f2` to `v1.8`, and nothing the venue sends changes.**
`git diff 9c3e1f2 v1.8 -- idl` in SpatialDDS-spec:

- `types.idl`: a comment, the BBox2D axis-order note.
- `vision.idl`: one appended enumerator, `PixelFormat.GRAY8 = 6`.

The owm, disco and core types are byte-identical, so the robot lane on
`spatialdds_ros` (still at `9c3e1f2`) is unaffected. The vision types'
TypeObjects change, which reaches only the dataset demos' camera lanes.

**QoS: the 19 registered rows agree, column for column.** The demo's
`qos_profiles.PROFILES` and the SDK's generated table match on reliability,
durability, depth and deadline for all 19. The differences are three profiles
the registry does not have:

| profile | columns (reliable, latched, keep_last, deadline) | nearest registered row |
| --- | --- | --- |
| `MODEL_LATCHED` | RELIABLE, TRANSIENT_LOCAL, 1, – | `MAP_META`, identical columns |
| `MODEL_FAST` | BEST_EFFORT, VOLATILE, 1, – | none: `POSE_RT` adds a 33 ms deadline |
| `MODEL_COMMAND` | RELIABLE, VOLATILE, 16, – | none: `EVENT_RT` is KEEP_LAST(64) |

§3.3.2 names no profile for `model_entity`, `model_pose` or `model_command`,
and 0.7.0 refuses a writer for any of them without `qos_profile=` (this
repository's spec queue, entry 5). So these three stay as deployment
profiles, declared once as `sd.dds.Profile`. `entity_binding` and
`navsat_status` are the other way round: `topic_types` assigns them profiles
the spec does not name (`MAP_META`, `POSE_RT`), and the SDK refuses rather
than guesses (spatialdds-py census, demo finding 6).

**Types the registry does not have.**

- `blob_chunk` is a demo-only registration, and the SDK needs `stream=` for
  it (spatialdds-py candidates 9.6).
- `FrameTransform` has no §3.3.2 row at v1.8, so model_service's frames lane
  is an extension lane under the SDK (queued below).
- The `oarc.*` types stay this repository's extensions.

**JSON: one difference on every recorded message, one break on every union.**

- **The recordings.** Every message of the five tracked recordings (5,387: 798
  Entity, 1,903 ModelCommand, 2,686 ModelPose) was decoded with both type
  trees and converted with both mappers. Each differs on exactly one path:
  `stamp.sec`, an integer in the demo dialect and a decimal string in N.1.
- **The types the recordings do not carry.** These were built with the SDK's
  own builders and crossed both ways:

  | type | differing paths | demo `from_json` of N.1 | SDK `from_json` of demo |
  | --- | --- | --- | --- |
  | Announce | 4, all int64 | accepts | accepts |
  | ContentAnnounce | 6, all int64 | accepts | accepts |
  | Entity | 1, int64 | accepts | accepts |
  | GeoAnchor | 7: `cov` and `geopose.cov` are tagged `discriminator` vs `type`, plus int64 | **refuses** ("'type' is not one of its cases") | **refuses** ("None is not a declared case") |

So the int64 difference is harmless to any reader that does not do arithmetic
on `sec`. The browser code coerces (`static/index.html:122`,
`web/src/app.ts:1404`). The union tag is a real break, in both directions, on
every type carrying a `CovMatrix`. Its readers and writers in this repository:

- `bridges/ros2_bridge/ros2_to_spatialdds.py:141, 228-229`
- `spatialdds_to_ros2.py:175` and `test_conversions.py`
- `multi_operator_fusion/spatialdds_types.py:292`
- `spatialdds_demo/payloads.py:33` (`COV_NONE`)
- `web/tests/fixtures/localize_response.json:9, 32`

This is where the two dialects die. The ruling asked for is that every outward
surface changes in one commit (below).

**Old and new types share a process.** One process, one domain, two
participants (the SDK always owns its own). An SDK `model_entity` writer and
the demo's `typed_transport.make_reader` with `spatialdds_idl18.Entity` read
each other's samples in both directions. So the migration can go one program
at a time, with every half-moved state interoperating on the bus.

**Topic names the SDK spells differently.** `sd.dds.topic_name` puts the
registered type name in the type segment and allows one stream segment.
`spatialdds/platform/fusion/track/v1` becomes `…/fusion/fused_track/v1`. The
dataset demos' sensor lanes have six segments
(`spatialdds/nuscenes/vision/<cam>/frame/v1`), which §3.3.1 does not have. The
mapping this census proposes is one rule:

- **scene** is the operator or dataset segment;
- **stream** is the sensor or lane instance;
- **type** is the registered type name.

| today | under the SDK |
| --- | --- |
| `spatialdds/platform/fusion/track/v1` | `spatialdds/platform/fusion/fused_track/v1` |
| `spatialdds/platform/fusion/coverage/v1` | `spatialdds/platform/fusion/oarc.fusion_coverage/v1` |
| `spatialdds/platform/events/trajectory_conflict/v1` | `spatialdds/platform/events/spatial_event/v1` |
| `spatialdds/platform/entity/binding/v1` | `spatialdds/platform/entity/entity_binding/v1` |
| `spatialdds/<op>/ego/pose/v1` | `spatialdds/<op>/ego/framed_pose/v1` |
| `spatialdds/<op>/plan/<op>_ego/trajectory/v1` (six) | `spatialdds/<op>/<op>_ego/planned_trajectory/v1` |
| `spatialdds/nuscenes/vision/<cam>/frame/v1` (six) | `spatialdds/nuscenes/<cam>/video_frame/v1` |
| `spatialdds/nuscenes/semantics/det3d/v1` | `spatialdds/nuscenes/semantics/detection3d/v1` |
| `spatialdds/blob/chunk/v1` (four) | `spatialdds/<scene>/blob/blob_chunk/v1` |

The venue's own lanes (`world/entity`, `world/model_pose`,
`world/model_command`, `frames/frame_transform`) and the well-known discovery
topics do not change. `deploy/aws/smoke_test.py:165` and the AWS stack assert
the fusion track name, so they change in the same commit.

## Verdicts, with the reasons the table cannot hold

The module table is in "Tables". These are the verdicts that are judgments.

**RETIRED: nothing needs it once the SDK is in.**

- **`json_mapping`**: the demo dialect. `sd.dds.to_json` / `from_json` is the
  gateway's own conversion (one code path, per the native-SDK ruling 5).
- **`typed_transport`**: `p.writer()` / `p.reader()`. Waits on S1 (drain), S4
  (IgnoreLocal) and S5 (matched).
- **`topic_types`**: the registry at the pin. The `oarc.*` extensions are
  declared beside their types. Runtime name-to-class lookup waits on S9.
- **`qos_profiles`**: the generated table. The three model profiles above
  stay, as three `sd.dds.Profile` declarations.
- **`topics`**: names from `sd.dds.topic_name`. `SCENE`, the web bridge's
  `TOPIC_SOURCE_*` labels, and the non-scene lanes (VPS, bootstrap, coverage
  replies, anchors) stay until S2 exists.
- **`tempo`**: `sd.Recency` has the same methods, constants and defaults. The
  demo's tempo tests run against `Recency` before `tempo.py` goes.
- **`dds_transport`**: the envelope transport. It leaves the package and
  becomes the benchmarks' own baseline arm, because a baseline is supposed to
  be raw. `require_dds_env` becomes `domain=` / `SPATIALDDS_DDS_DOMAIN`, with
  no silent 0.
- **`spatialdds_idl18/`** (3,813 lines, generated): `spatialdds.dds.types`,
  the whole v1.8 tree from spatialdds-py's generator. **One consequence:**
  `spatialdds_ros` 0.3.0 ships a top-level `spatialdds_idl18` of its own, and
  this repository's root copy wins on `sys.path` today. Once this copy goes,
  the robot lane imports the library's own. `tests/test_idl_trees_agree.py`
  then has a different subject: the library's tree against the SDK's types,
  for the lanes the robot uses.

**REPLACED, the module's job done by the SDK.**

- **`discovery_bus`**: `p.announce()`, `p.reader("Announce")`,
  `p.reader("ContentAnnounce")`, and a ContentAnnounce writer with
  `on_exit="withdraw"`. This is where the brief's three asserted fixes land
  (the valid-sample departure, the Depart lane, the purge on no-writers),
  because they come with the SDK's reader. Waits on S1, and on S3 for the AR
  catalogue's transforms.
- **`stream`**: announce-driven, multi-topic, cross-scene endpoints. The
  heaviest dependency of anything here: S1, S2, S3, S4, S9.
- **`blob`**: `sd.dds.chunk`, `Reassembler`, `blob_ref`. The two
  implementations' chunk and reference formats are compared before the
  demo's goes; this census did not compare them.

**STAYS: the venue's own logic, or a convention with no SDK form.**

- **The venue:** `model_service`, `duck_mover`, `pond_watch`, `robot_bridge`,
  `keepout`, `plaza` and `catalog_semantics`. Their transport moves; their
  logic does not. `model_service`'s retire flow becomes `withdraw(key,
  reason=)`, which is the same tombstone and dispose, with the SDK settling on
  acknowledgements rather than a fixed 1.5 s.
- **`service_bus`**: the request/reply convention holder until 1.9, as the
  native-SDK ruling 4 has it. Its lanes are not scene-shaped, so they move
  onto SDK writers only with S2. Until then it is the one module that keeps
  raw cyclonedds.
- **`content_catalogue`**: the venue's seed-to-record mapping. Its records
  build through `sd.content_announce` / `content_manifest` where those fit.
  The builder has no `transforms=` (S8), so the placement is added to the
  document.
- **`discovery_http`**: HTTP search semantics, not bus plumbing. Its
  docstring still says 1.7, which is an editorial fix only.
- **`manifest_resolver`**: offline, bundled resolution that the AR flow runs
  on without a network. `sd.connect(base).resolve()` needs a live endpoint.
- **`absent`**, and `payloads`' absent constants: 0.7.0 has no absent-value
  constants (S6).
- **`payloads`'** fusion shapes (`detection3d`, `detection_set`): demo
  payloads. Its `stamp`, `frame_ref` and `COV_NONE` are REPLACED.
- **`spatialdds_demo_idl18/`** (120 lines): the `oarc.*` extension types.
  `scripts/generate_types.py` shrinks to generating this tree only.
- **`tests/cross_era/spatialdds_idl/`**: the cross-era test's vendored
  pre-1.8 bindings. A fixture, and excluded from the consumer counts.

## Outward surfaces that change

The ROS adoption's census was amended because it had not enumerated every
field the page reads. So these are the surfaces whose bytes change, listed
before anything is built:

- **The browser.** Bridge `/ws` and `/v1/stream` carry `to_json` output.
  Unions change their tag and int64 becomes a string. The binding at :8089
  already serves N.1 through spatialdds' `webjson` (`binding.py:230-237`).
- **HTTP.** `/v1/localize` returns a VpsResponse, so its `cov` changes tag.
  `web/tests/fixtures/localize_response.json` is the AR parser's fixture for
  it.
- **MQTT.** Every bridged payload.
- **The MCAP bridge's recordings.** JSON plus jsonschema, with schemas
  generated from the demo dialect (`schema_registry.py:17-20`). They change
  shape, and the generator moves onto the N.1 schemas the SDK ships. The
  tracked `recordings/*.mcap` are CDR and do not change.
- **Topic names.** The rename table above, the smoke test and the AWS stack.
- **The domain.** Runs that set no domain are refused rather than joining
  domain 0. The AWS stack sets `SPATIALDDS_DDS_DOMAIN=0` (`spatialdds_stack.py:138-148`).
  The bootstrap server's hard-wired `DomainParticipant(0)` becomes an explicit
  `domain=0`, because that domain is its design.

## Filings for spatialdds-py

spatialdds-py is read-only in this batch, so these are written here. Each is a
gap the first consumer found, with where it was found. None is a patch.

- **S1. No public non-blocking drain.**
  - *What 0.7.0 has:* `Reader.events()` blocks, and the drain is the private
    `_events()` (`_participant.py:373`).
  - *Where it bites:* every live reader here drains in a loop it owns:
    - `model_service.py:787` and `duck_mover.py:308-313`;
    - `keepout_node.py:165`, inside an rclpy timer;
    - `web_bridge/server.py:149-170`, inside sync FastAPI handlers;
    - `nuscenes/subscriber_rerun.py:98-111`, twenty readers on one thread;
    - `ros2_bridge/bridge_node.py:589-594`, inside an rclpy timer.
  - *Smallest change:* make `Reader.take()` public, with `EndOfReplay`
    emitted once, on the first take after the settle.
- **S2. No lane outside `spatialdds/<scene>/…`.**
  - *Unreachable today:*
    - the VPS lanes (`spatialdds/vps/query|result/v1`);
    - the oarc bootstrap lanes;
    - coverage reply topics named by the asker (`service_bus.py:181-206`,
      KEEP_ALL);
    - anchor deltas (`spatialdds/anchors/<set>/delta/v1`);
    - another scene's lanes (all four bridges and the MCAP replayer).
  - *Smallest change:* a `topic=` that takes a full name, validated against
    §3.3.1's grammar and refused on a well-known topic, with
    `history=`/`depth=` overrides for reply readers.
- **S3. The announce cannot carry `transforms`, and is one per participant.**
  - *Found at:* `spatialdds_catalog_server.py:167` (transforms),
    `synthetic_publisher.py:500-508` (N+1 services), and
    `replayer.py:178-191`, `mqtt_bridge`, `test_live.py:164-170` (relayed
    announces).
  - *Smallest change:* `transforms=` on `p.announce()`, and a documented
    relay writer for bridges, marked as not the participant's own claim.
- **S4. No IgnoreLocal on readers.** The MQTT and ROS 2 bridges prevent loops
  with `Policy.IgnoreLocal.Participant` (`mqtt_bridge/bridge.py:138-142`,
  `bridge_node.py:586-587`). *Smallest change:* `ignore_local=True` on
  `p.reader()`.
- **S5. No matched status on writers.** `duck_mover.py:462`,
  `scripts/move_duck.py:101`, `reshape_pond.py:95` and `retire_entity.py:67`
  wait for a matched reader before commanding. *Smallest change:*
  `Writer.matched()` and `wait_matched(timeout)`.
- **S6. No absent-value constants.** `absent.py`, `payloads.ABSENT_*`, the
  nuScenes and DeepSense converters, and `spatialdds_validation.py:458, 474`.
  The spatialdds-py census mapped these to "absent-value constants beside the
  types", which 0.7.0 does not ship.
- **S7. A participant cannot be shared with a library that takes a
  `DomainParticipant`.**
  - *Found at:* `robot_bridge.py:310-379`, which hands its participant to
    `spatialdds_ros` (`RobotAdapter`, `already_published`).
  - *Not needed for this batch:* rebasing ROS onto the SDK is out of scope.
    The robot lane keeps its own raw participant beside an SDK one (measured
    above to interoperate), as a labelled workaround.
- **S8. `content_announce` has no `transforms=`.**
  `content_catalogue.py:238-253` carries the placement and frame anchor.
- **S9. No public lookup from a registered type name to its class.** The
  bridges and the replayer resolve a `TopicMeta.type` string at runtime. The
  SDK's lookup is the private `_types_class`. Importing
  `spatialdds.dds.types.<module>` by FQN works, but it is layout no one
  promised.

**Corrections to spatialdds-py's census fit map.** These were measured
against the release, and `--check-sdk` refuses each if planted:

- `blob.*` maps to `sd.dds.chunk` / `Reassembler` / `blob_ref` plus a plain
  writer. There is no `p.blob_writer()`.
- `qos_profiles.MODEL_LATCHED` has no "registry default for `model_entity`":
  §3.3.2 names none, and 0.7.0 refuses the writer without `qos_profile=`.
- The absent-value constants do not exist (S6).

## Spec queue

Proposed for this repository's `docs/owm-1.8-spec-queue.md`:

- **`FrameTransform` has no §3.3.2 registration.** Every venue publishes its
  georeference on a lane the registry cannot name, so an SDK writer has to
  declare it as an extension. `model_service` and the binding both use
  `spatialdds/<scene>/frames/frame_transform/v1`.
- **§3.3.1 has no sensor-instance segment.** Six cameras of one type in one
  scene are distinguished only by the stream segment, under the mapping
  proposed above. The datasets' six-segment names show that real deployments
  reach for an instance segment first.
- **Already queued, cited rather than refiled:** entry 5 (model lanes have no
  profile), spatialdds-py candidates 9.5 (VPS lane names exist only in an
  example) and 9.6 (the blob lane is unnamed).

## Defects found in passing (this repository's, not the SDK's)

Each is fixed in the migration commit that touches its file, and named there.

- **`multi_operator_fusion/infrastructure_publisher.py:239`** iterates
  `det_payload["detections"]`, and its builder emits `dets`. Measured by
  calling `make_detection3d_payload`: the keys are `dets, frame_ref, has_tile,
  set_id, source_id, stamp, tile_key`. So the publisher raises `KeyError` on
  every frame that reaches it.
- **The dataset publishers never announce** (read): the fusion, nuScenes,
  infrastructure and DeepSense ones. `multi_operator_fusion/run_demo.py`
  pairs them with `fusion_service` and `subscriber_rerun`, which discover only
  through announces.
- **The MQTT bridge's inbound announces fail** (read).
  `topic_mapping.py:50` infers a type name that `topic_types.resolve` refuses,
  and `bridge.py:270` counts each one as an inbound error.
- **`model_service --quiet` is parsed and never used** (read: `:692`, `:722`).
- **`synthetic_publisher.py:13`** documents `oarc.detection3d_velocity`; the
  code uses `detection3d`.
